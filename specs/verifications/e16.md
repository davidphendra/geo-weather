  ```json
  { "version": "0.1.0-alpha", "informationalVersion": "0.1.0-alpha+0b4e50c75d",
    "commit": "0b4e50c75d40a9350c89027eb9cb455c66db37c7", "publicRelease": "false", "builtAtUtc": "…" }
  ```
- `scripts/check-version.sh` returns 0 for a real version and 1 for `0.0.0*`, a missing file, or no arg.
- Assemblies carry `AssemblyVersion=0.1.0.0`, `AssemblyFileVersion=0.1.0.<commit>`,
  `AssemblyInformationalVersion=<semver>+<commit>` (NBGV).
- Pipeline: `checkout: self` `fetchDepth: 0`; version guard after publish; artifact
  `webapp-$(Build.BuildNumber)` referenced identically by CI publish and Deploy download/package.

## Known limitation / follow-up

- The Microsoft OpenTelemetry distro configures its **logging** resource separately from metrics/traces, so
  the log resource shows the SDK default `service.name` (`unknown_service:Weather.WebUI`) and does not carry
  `service.version`. Metrics and traces do. Logs still carry the version via the structured startup line
  (`Version`/`Commit`). Fixing the log resource would require `OTEL_SERVICE_NAME` / `OTEL_RESOURCE_ATTRIBUTES`
  deployment configuration or a distro resource hook — logged as a follow-up, not a regression.
