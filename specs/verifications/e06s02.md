## What was built
- Client DTO mirrors: `CountryModel`, `CityModel`, `WeatherReportModel` (+ `LocationModel`,
  `TemperatureModel`, `WindModel`), `FavoriteCityModel`, `WeatherNoteModel`, `AddFavoriteModel`,
  `AddNoteModel`, `ApiProblem`, `ApiResult<T>`, `WeatherApiException`.
- `WeatherApiClient` — typed, same-origin client. Absolute request URIs are built from
  `NavigationManager.BaseUri` (D7); there is **no** `Api:BaseAddress`. Problem-Details-aware failures
  (`WeatherApiException` carrying status + stable `code`). GETs throw on failure; writes return
  `ApiResult<T>` with the real status and raw JSON.
- `WeatherExplorerModel` — the country → cities → weather cascade plus `Loading`/`Error` state,
  extracted from the component so it is testable offline.
- DI: `AddHttpClient<WeatherApiClient>()` and `AddScoped<WeatherExplorerModel>()`.

## Covered behaviour
- Country catalog and full weather payload parsing (every metric).
- Requests are absolute on the app origin: `https://test.local/api/weather/London?countryCode=GB`.
- 404 → `RESOURCE_NOT_FOUND`, 502 → `DEPENDENCY_UNAVAILABLE` mapped to `WeatherApiException`.
- `AddFavoriteAsync` returns `201` + the created resource.
- Cascade: initialize loads countries → first country's cities → first city's report.
- A weather failure sets `Error` (code `DEPENDENCY_UNAVAILABLE`) and clears `Report`/`Loading`.
