# Verification — e11s04 Create the SQLite directory for configured connection strings

Date: 2025-10-15
Branch: `feature/e10-single-host`
Result: **PASS**

## Reproduced defect
Published host, `ConnectionStrings__Geography=Data Source=/tmp/weather-nonexistent/nested/geography.db`:
```
Microsoft.Data.Sqlite.SqliteException (0x80004005): SQLite Error 14: 'unable to open database file'.
Unhandled exception. Microsoft.Data.Sqlite.SqliteException …
```
Host never started (`curl` returned `000`).

## Fix
`Weather.WebUI/Configuration/SqliteConnectionDirectory.EnsureCreated` + host loop over `ConnectionStrings`
creates the parent directory of every resolved SQLite connection string (default **and** override) before
`Database.Migrate()` runs.

## Re-test after fix
Same scenario: `GET /api/countries` → `200`; `/tmp/weather-nonexistent/nested/geography.db` created.

## Clarification on the original concern
Shipping the `.db` files is **not** required. With the default path the app creates the directory and the
databases at runtime (verified in e11s03). The only failure was a configured path whose directory did not exist;
that is now provisioned. The remaining deployment requirement is a **writable, persistent** location.
